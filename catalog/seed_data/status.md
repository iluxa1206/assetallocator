# Astra AM — Investment Dashboards · Техническая документация

Документ описывает логику, структуру, формулы и источники данных двух
HTML-дашбордов инвестиционной компании Astra AM (Asset Management).

Дата актуализации: 14 мая 2026.

---

## 1. Состав проекта

| Файл | Назначение | Аудитория |
|---|---|---|
| `sales_dashboard.html` | Подбор инвестиционной стратегии для клиента: ввод суммы, выбор риск-профиля и валютной стратегии, готовая аллокация с диаграммами, бэктест, экспорт | Менеджеры по продажам (sales desk) |
| `portfolio_compare.html` | Аналитический инструмент: ручная сборка портфеля фондов и композитного индекса, сравнение исторической динамики | Аналитики |

Оба файла — автономные одностраничные приложения. Весь код (HTML, CSS, JS),
а также данные фондов и индексов вшиты внутрь файла. Внешние зависимости
подгружаются с CDN: Chart.js (графики) и SheetJS (экспорт в Excel,
только в sales-дашборде).

## 2. Источники данных

### 2.1. Исходный файл фондов

Данные приходят в Excel-файле (последняя версия — `фонды_111-11.xlsx`).
Структура:

- **Лист1** — котировки паёв фондов. Для каждого фонда пара колонок:
  дата и цена пая в рублях. Около 55 точек на фонд (концы месяцев),
  начиная с 2021-12-31.
- **Лист2** — значения рыночных индексов, валютных курсов и инфляции
  на те же даты. 73 строки, с 2020-12-31 (для CPI нужны исторические
  значения на 12 месяцев назад).

### 2.2. Файл аллокаций

Модельные доли портфелей приходят отдельным файлом (`Книга1.xlsx`).
Содержит таблицу: строки — фонды, столбцы — комбинации риск-профиля
и валютной стратегии. Значения — доли в долях единицы (0.1 = 10%).

### 2.3. Десять фондов

| Ключ | Название | Родная валюта | Бенчмарк |
|---|---|---|---|
| `R5` | Хедж-фонд Р5 | RUB | RGBITR |
| `D5` | Хедж-фонд Д5 | USD | Cbonds ЗО (RUB) |
| `Yu5` | Хедж-фонд Ю5 | CNY | RUCNYTR (RUB) |
| `D1` | Хедж-фонд Д1 | USD | Cbonds ЗО (RUB) |
| `VO` | Валютные облигации с выплатой дохода | USD | Cbonds ЗО (RUB) |
| `Aplus` | Хедж-фонд А+ | RUB | MCFTR |
| `A12080` | Российские акции 120/80 | RUB | MCFTR |
| `R1` | Облигации Р1 | RUB | RGBITR |
| `M3` | Хедж-фонд М3 | GLD (золото) | GLDRUB |
| `Liq` | Фонд денежной ликвидности | RUB | RUSFAR |

Цены паёв всех фондов хранятся **в рублях**. «Родная валюта» — это
валюта, в которой фонд оперирует и в которой считается его собственная
доходность (используется в FX-декомпозиции).

Особенности отдельных фондов:

- **VO** (Валютные облигации с выплатой дохода) — фонд с выплатой
  купонов. Цена пая снижается на величину выплат, поэтому «бумажная»
  доходность пая отрицательна (−1.30% за весь период). Реальная
  доходность инвестора выше — выплаты идут «в карман» и в текущей
  модели отдельно не реинвестируются.
- **M3** — стратегия привязана к золоту. Родная валюта — `GLD`
  (граммы золота), пересчёт через курс GLDRUB. **Считается валютным
  активом**, не рублёвым.
- **Liq** (Фонд денежной ликвидности) — синтетический ряд,
  восстановленный из индекса RUSFAR: нормирован к 1000 на стартовую
  дату, далее повторяет динамику RUSFAR. 61 точка (длиннее прочих).

### 2.4. Индексы, курсы и инфляция

В каждой записи `INDICES` (одна на дату):

| Поле | Смысл |
|---|---|
| `RUSFAR` | Ставка денежного рынка |
| `RGBITR` | Индекс ОФЗ (гособлигации РФ) |
| `MCFTR` | Индекс российских акций полной доходности |
| `CbondsZO_RUB` | Индекс валютных (замещающих) облигаций в рублях |
| `RUCNYTR_RUB` | Индекс юаневых облигаций в рублях |
| `GLDRUB` | Цена золота в рублях |
| `USDRUB` | Курс доллара к рублю |
| `CNYRUB` | Курс юаня к рублю |
| `CPI_rub` | Инфляция РФ, % годовых (YoY) на эту дату |
| `CPI_USD` | Инфляция США, % годовых (YoY) |
| `CPI_cny` | Инфляция Китая, % годовых (YoY) |

Индексы и курсы — абсолютные значения на дату. CPI — это **годовые
ставки** (YoY, «год к году»), а не накопленный индекс; накопленный
уровень цен вычисляется отдельно (см. раздел 5.4).

### 3.4. Функция `computeAllocation()`

Возвращает доли фондов для текущего состояния:

- если `state.manual` — возвращает `state.manualFunds`;
- если `risk === 'base'` — возвращает `ALLOCATIONS.base`;
- иначе — `ALLOCATIONS[risk][ccy]`.

### 3.5. Композитный индекс

Композитный индекс — это бенчмарк портфеля, собранный из рыночных
индексов. Функция `computeIndexWeights(fundWeights)`:

- если `state.manual` — возвращает `state.manualIndices`
  (заданные пользователем доли индексов);
- иначе — суммирует доли фондов по их бенчмаркам. Например, если
  R5 имеет 10% и R1 имеет 30%, и оба привязаны к RGBITR, то
  RGBITR в композите получает 40%.

### 3.6. Ручной режим (панель «Индивидуальный портфель»)

При активации ручного режима:

1. `state.manual = true`.
2. `manualFunds` заполняется текущей авто-аллокацией (отправная
   точка для правок).
3. `manualIndices` заполняется бенчмарками этой аллокации.
4. Кнопки риск-профиля и валютной стратегии гаснут (`disabled`).

Доли в ручном режиме могут не суммироваться в 100%. Для денежных
расчётов (суммы в легенде, таблицах) веса нормализуются:
`нормированный_вес = вес / сумма_весов × 100`. Графические ряды
(`buildPortfolioSeries`, `buildBenchmarkSeries`) нормализуют веса
самостоятельно, поэтому корректны при любой сумме.

Кнопка «Сбросить» в каждой колонке: для фондов — возвращает доли
текущей стратегии; для индексов — пересобирает из бенчмарков текущих
ручных долей фондов. Кнопка «Вернуться к стратегии» — полный выход
из ручного режима.

## 5. Формулы и методология

### 5.1. Пересчёт цен в базовую валюту

Цены паёв и индексы хранятся в рублях. Для отображения в выбранной
базовой валюте применяется курс на каждую дату.

Курс «рубль → базовая валюта»:
```
rubToBaseRate(date, base):
  base == RUB  →  1
  base == USD  →  1 / USDRUB[date]
  base == CNY  →  1 / CNYRUB[date]
  base == GLD  →  1 / GLDRUB[date]
```

Цена пая фонда в базовой валюте:
```
fundPriceAt(fund, date) = price_RUB[fund, date] × rubToBaseRate(date, base)
```

### 5.2. Кросс-курс между любыми двумя валютами

```
fxRate(from, to, date):
  если from == to  →  1
  rubPer(ccy):  RUB→1, USD→USDRUB, CNY→CNYRUB, GLD→GLDRUB
  результат = rubPer(from) / rubPer(to)
```

`rubPer(ccy)` — сколько рублей стоит единица валюты. Деление даёт,
сколько единиц `to` стоит единица `from`.

### 5.3. Нормированный ряд портфеля

Все ряды на графике нормированы к 100 на стартовую дату.

```
buildPortfolioSeries(weights, dates):
  total = сумма всех весов
  norm[k] = weight[k] / total          (нормировка к долям единицы)
  startPrice[k] = fundPriceAt(k, dates[0])

  для каждой даты d:
    value(d) = Σ  norm[k] × (fundPriceAt(k, d) / startPrice[k])
    ряд[d] = value(d) × 100
```

То есть значение на старте всегда 100, далее — взвешенная сумма
относительных изменений цен фондов.

Композитный индекс `buildBenchmarkSeries` строится аналогично, но
из значений индексов вместо цен фондов, с весами из
`computeIndexWeights`.

### 5.4. Накопленная инфляция (CPI)

В данных CPI — это **годовые ставки YoY** (% за последние 12 месяцев
на каждую дату). Накопленный индекс уровня цен строится по точной
формуле:

```
CPI_level[t] = CPI_level[t − 12 месяцев] × (1 + YoY[t] / 100)
```

Это математически точное соотношение, прямо вытекающее из
определения «год к году». Алгоритм (`getGlobalCpiLevels`):

1. Якорь: на самой ранней доступной дате уровень = 1.0.
2. Для каждой следующей даты ищется дата ровно на 12 месяцев раньше.
   Если найдена — применяется формула выше.
3. Если 12 месяцев назад точки нет (только в первые 12 месяцев
   ряда) — используется приближение через месячное распределение:
   `level[t] = level[t−1] × (1 + YoY[t]/100)^(1/12)`.
4. Глобальная карта уровней кешируется.

Для конкретного окна бэктеста значения нормализуются к 100 на
стартовой дате окна:
```
CPI_ряд[d] = CPI_level[d] / CPI_level[dates[0]] × 100
```

Линия инфляции следует **базовой валюте**: при базе RUB берётся
`CPI_rub`, при USD — `CPI_USD`, при CNY — `CPI_cny`. Для базы GLD
инфляция не определена.

### 5.5. Метрики (`calcMetrics`)

На вход — нормированный ряд (`series`) и массив дат. Вычисляются:

**Доходность за период:**
```
totalRet = series[последний] / series[первый] − 1
```

**Среднегодовая доходность (CAGR):**
```
days  = (последняя дата − первая дата) в календарных днях
years = days / 365
CAGR  = (series[последний] / series[первый]) ^ (1 / years) − 1
```
База — **365 календарных дней** (не торговые дни).

**Волатильность (годовая):**
```
доходности r[i] = series[i] / series[i−1] − 1   (по соседним точкам)
mean     = среднее r
variance = Σ (r[i] − mean)² / N
vol      = √variance × √12
```
Данные месячные, поэтому годовое масштабирование — умножение на √12.

**Максимальная просадка:**
```
peak  = бегущий максимум ряда
DD(t) = series[t] / peak − 1            (всегда ≤ 0)
maxDD = минимальное значение DD за период
```

### 5.6. Сумма инвестиций в базовой валюте

Клиент вводит сумму в своей валюте (`amountCcy`). Для расчётов она
переводится в базовую валюту по курсу на стартовую дату:
```
investedBase = amount × fxRate(amountCcy, baseCurrency, startDate)
```

Денежный результат портфеля:
```
endedBase  = investedBase × (1 + totalRet)
profit     = endedBase − investedBase
```

### 5.7. Финансовый результат по фондам

Для каждого фонда с долей > 0 (таблица «Финансовый результат
по фондам»):
```
доля_норм   = вес_фонда / сумма_весов
сумма_старт = investedBase × доля_норм
доходность  = fundPriceAt(фонд, конец) / fundPriceAt(фонд, старт) − 1
сумма_конец = сумма_старт × (1 + доходность)
результат   = сумма_конец − сумма_старт
вклад_пп    = доля_норм × доходность × 100   (в процентных пунктах)
```
Сумма вкладов всех фондов в процентных пунктах равна общей
доходности портфеля.

### 5.8. FX-декомпозиция

Раскладывает результат каждого фонда на две части: что заработал
сам фонд в своей родной валюте, и что добавило/отняло изменение
курса. Расчёт ведётся **в валюте вложения** (`amountCcy`).

Обозначения для фонда:
- `native` — родная валюта фонда;
- `investedInCcy` — сумма, приходящаяся на фонд, в валюте вложения;
- `pNative0`, `pNativeN` — цена пая в родной валюте на старте и конце;
- `fx0`, `fxN` — курс «родная → валюта вложения» на старте и конце.

```
investedNative = investedInCcy / fx0          (перевод в родную валюту)
N              = investedNative / pNative0    (число купленных паёв)
ended          = N × pNativeN × fxN           (итог в валюте вложения)

Доходность фонда = N × (pNativeN − pNative0) × fxN
Эффект курса     = investedNative × (fxN − fx0)
```

Тождество (выполняется точно):
```
investedInCcy + Доходность_фонда + Эффект_курса = ended
```

Если родная валюта фонда совпадает с валютой вложения, эффект
курса равен нулю.

Проверка корректности проводилась против эталонного файла
`Книга2.xlsx`: для фонда Д5 совпадение до копейки (фундаментал
+232 750.39 ₽, FX-эффект −34 355.04 ₽).

### 5.9. Распределение по валютам

```
getCurrencyBreakdown(weights):
  для каждого фонда прибавить его вес к группе его родной валюты
  результат: { RUB, USD, CNY, GLD }
```

В кольцевой диаграмме «Распределение по валютам» показываются
**два сегмента**: «Рубль» и «Валюта», где Валюта = USD + CNY + GLD.
**Золото (GLD) всегда относится к валютной части, не к рублёвой.**
В легенде под диаграммой — детализация: рубль отдельной строкой,
затем валютная группа с подстроками USD / CNY / GLD.

## 6. Подбор периода и обработка пропусков

Функция `findValidDates(weights)`:

1. Берёт диапазон дат между `startDate` и `endDate`.
2. Оставляет только те даты, на которые есть цена у **всех** фондов
   с ненулевой долей.

Это защищает от «дыр»: если у фонда нет котировки на часть периода,
такая дата исключается из расчёта целиком (для всех рядов), чтобы
сравнение оставалось корректным. Если данных на части периода
не хватает, в таблицах выводится «недостаточно данных».

### 7.1. PDF

## 8. Темы оформления

Светлая тема — по умолчанию. Тёмная — в стиле финансовых
терминалов (глубокий сине-чёрный фон, тёплый золотой акцент).
Реализованы через CSS-переменные: светлая в `:root`, тёмная
в `:root[data-theme="dark"]`. Цвета графиков (линии, тултипы,
сетка, палитры диаграмм) читаются из CSS-переменных и
пересоздаются при переключении темы.

Шрифт — Gilroy (подключается с CDN), запасные — системные
sans-serif.

## 9. Ключевые методологические решения

1. **CAGR считается по календарным дням**, база 365.
2. **Накопленная инфляция — по точной YoY-формуле** (уровень
   через значение 12-месячной давности), а не через перемножение
   месячных приращений.
3. **FX-декомпозиция использует аддитивную модель** «в деньгах»
   (не мультипликативную), расчёт в валюте вложения. Тождество
   «вложено + фундаментал + FX = стало» выполняется точно.
4. **Золото (M3 / GLD) — валютный актив**, во всех расчётах
   валютной экспозиции суммируется с USD и CNY, не с рублём.
5. **Инфляция — отдельная опциональная линия** на графике,
   не входит в композитный индекс. Следует базовой валюте.
6. **VO использует цены пая с учётом выплат** — цена снижается
   на величину распределённого дохода; «бумажная» доходность
   пая поэтому отрицательна.
7. **Композитный индекс собирается из бенчмарков фондов** —
   в авто-режиме пропорционально долям фондов, в ручном —
   задаётся пользователем независимо.
8. **Volatility годовая, по месячным данным** — масштабирование
   стандартного отклонения месячных доходностей на √12.

## 10. Технические ограничения

- Файлы автономны, но требуют доступа к CDN (Chart.js, SheetJS,
  шрифт Gilroy). Без интернета графики и экспорт в Excel не
  работают.
- Браузерное хранилище (localStorage) не используется — выбор
  темы и параметров не сохраняется между сессиями.
- Все данные вшиты в файл на момент его сборки. Обновление
  котировок требует пересборки файла из нового Excel.
- Расчёты идут по точкам данных (концы месяцев); внутримесячная
  динамика не моделируется.
